# Dictionary downloads with the same name

The download catalogue may list several dictionaries with the same display name and different sources. Each source stays selectable. For entries sharing a display name, a URL-derived suffix distinguishes their installation directories and StarDict booknames, so each can be enabled, disabled, selected in presets, and looked up independently. While the display name and same-name catalogue membership stay unchanged, downloading the same entry again prepares the replacement in a staging directory and only replaces the existing version after extraction and identity updates succeed. Failed preparation keeps the previous dictionary and its disabled and ordering settings. If publishing the replacement fails, the old directory is restored; if the filesystem also refuses restoration, the error reports the retained recovery directory instead of deleting it.

Staging and recovery directories use the reserved `.koreader-dict-download-` prefix next to the installation. They are excluded from dictionary discovery and lookup, even if cleanup fails. Recovery files are kept for manual recovery when both replacement and restoration fail. Reinstallation needs room for the downloaded archive and a newly extracted replacement while the installed copy is retained; peak storage includes both extracted versions and the archive. If cleanup fails, staging files also continue to occupy space. After checking which version to keep, users may remove leftover staging directories manually; preserve any `previous` directory until recovery is complete.

Older installations do not record their download URL. An existing directory without a URL identity is therefore preserved, together with its disabled and ordering settings; KOReader cannot safely infer which source created it. Re-downloading after an upgrade can leave both the older copy and the newly identified version installed. If they are duplicates, remove the older copy manually after checking which version to keep. A different same-name dictionary is never removed automatically based on its display name.

The installation path also depends on the catalogue display name and whether that name has conflicting sources. If a later catalogue changes either, downloading the URL again may create another installation; existing copies and their path-based disabled and ordering settings remain on their original paths. Check the copies before manually removing one or setting preferences for the new path. There is no migration across such catalogue changes.
